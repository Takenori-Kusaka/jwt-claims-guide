# レビュー後に見つかった欠陥の記録（escaped defects）

レビューを閉じた後に見つかった設計の欠陥を記録します。目的は、レビューの問いの一覧・カタログ・対応表・lint のどこに穴があったかを知り、そこに戻すことです。欠陥を見逃したレビュアーを評価するためのものではありません。

- 作成方法：本資料は生成AI（Claude）を使って作成し、筆者が確認して公開しています。人による点検は未実施
- 記録は、この表に行を足す PR で行います。1 件ごとに、戻した先の PR か issue を書き、それが閉じるまで「戻し済み」にしません

## 記録する欠陥

- レビューが閉じた後（設計書の PR がマージされた後）に見つかった、設計の誤り
- 見つけた場所は問いません：実装・テスト・運用・事故・後のレビュー・パイロット（#9）・誤りを埋め込んだ設計書の測定（#12）
- 同じ設計書を後で別のレビュアーが読み直して見つけた指摘も含めます（例：シナリオ A の PR #28 の再点検で出た Minor）

## 見逃した理由の区分

| 区分 | 意味 | 戻す先 |
| --- | --- | --- |
| 問いが無い | 観点書・テンプレートのどの問いにも当たらない | 観点書に問いを足す |
| 欄が無い | 問いはあるが、Yes／No を付けるために見る欄が設計書・台帳に無い | テンプレート（#4）・台帳（#3）に欄を足す |
| 答えを誤った | 問いも欄もあり、レビュアーが Yes と付けた | 問いの文言・対比表を直す。見る欄の書き方を具体にする |
| 一覧の外 | カタログ・対応表の外の場面 | カタログ（#2）・対応表（#22）に戻す |
| 機械で拾えた | lint の規則・実行テストがあれば拾えた | lint（#6・#18）・実行テスト（#8）に渡す |

## 戻し方

1. 区分に応じて、戻す先の issue にコメントするか PR を出す
2. 観点書に問いを足すときは、問いに「較正で追加」または「欠陥 <ID> から追加」と書き、この表の ID を添える
3. 戻した PR がマージされたら、状態を「戻し済み」にする
4. 同じ区分の欠陥が続くときは、[metrics.md](metrics.md) の指標と合わせて、関門 2（#9）の材料にする
