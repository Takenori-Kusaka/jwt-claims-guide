# レビューレポートの様式

設計書の PR ごとに 1 件書きます。設計書と同じディレクトリに `review-report.md`（複数回なら `review-report-<日付>.md`）として置くか、PR のコメントに貼ります。記入例は `templates/examples/scenario-b/review-report.md` です。

- 作成方法：本資料は生成AI（Claude）を使って作成し、筆者が確認して公開しています。人による点検は未実施
- レビュアーが答えるのは、短い一覧（[short_list.md](short_list.md)）の問いだけです（#56）。「問いごとの回答」（8.）には答えた問いだけを書き、開いた問いで辿ったことは、様式の後ろに節を足して書きます（下の「様式の後ろに足す節」）
- 節の見出し・1. の項目・表の見出しは、道具（`tools/review_check.py --report`・`tools/review_record.py report`）が確かめます。この版では変えていません（記録の形の見直しは #62・#67）

## 語彙

<a id="origins"></a>

### 指摘の出どころ（5 種）

| 出どころ | 意味 |
| --- | --- |
| テンプレート項目 | 設計書のテンプレートの欄（項目 ID）の「検討の問い」から見つけた |
| 観点 | 観点書（perspectives.md）の問い ID から見つけた |
| カタログ外の質問 | `q-outside-catalog` など、カタログ・一覧の外を問う質問から見つけた |
| テンプレート外 | どの欄・問いにも当たらない、レビュアーの気づき |
| LLM | LLM の一次スクリーニングが出し、レビュアーが採用した |

<a id="kinds"></a>

### 指摘の種別（5 種）

| 種別 | 意味 | 書くこと |
| --- | --- | --- |
| 理由の不備 | 判断は妥当かもしれないが、理由が判断を支えていない | 理由の採点基準の観点（RR1〜RR7） |
| 前提の誤り | 判断が依存する事実（仕様・IdP の挙動・製品の制約）が誤っている | 正しい事実と出どころ |
| 実装とのずれ | 設計書の記述と、台帳・lint の結果・実装・実測が食い違う | 食い違う 2 つの場所 |
| 候補の漏れ | 検討すべき候補（仕組み・場面・主体・経路）が検討されていない | 漏れた候補 |
| 目的と仕組みの不一致 | ユースケースの問いと、選んだ仕組みが答える問いが違う | **どの問いの取り違えか**（判断の木の節の ID、`questions.yaml` の ID。例：`q-peer` を `req_wl` で答えた） |

<a id="severities"></a>

### 重大度と判定

- 重大度：Blocker（偽造・なりすまし・他テナントのデータに届く）／Major（権限の誤り・剥奪の遅れ・監査が崩れる）／Minor（記述の誤り・保守で壊れる）
- 判定：採用（直す）／却下（指摘が誤り。理由を書く）／保留（専門家に回した・追跡 issue で決める）
- 対応の状態：未着手／対応中／直した／直さない（理由を確かめた）

<a id="form"></a>

## 様式（ここから下を写す）

```markdown
# レビューレポート：<設計書の名前>

## 1. 基本情報

| 項目 | 値 |
| --- | --- |
| 対象 | 設計書のパスとコミット（版） |
| Lite／Full | 設計書の判定と、レビュアーの確認の結果 |
| 実施した手順の段 | procedure.md の段の番号（例：0〜8。省いた段と理由）。段 1 で読んだ設計の性質（short_list.md の 1.）も書く |
| レビュアーと役割 | 名前（または LLM のセッションとモデル）と、担当した段・役割。1 名なら切り替えの順と日付 |
| 実施日 | YYYY-MM-DD |
| 使った教材の版 | templates/review の template_version とコミット |
| CI の結果 | claim_lint の error・warn・info の件数と、設計書の 1. との一致 |
| 抜き取りの結果 | 理由の採点：抜き取りの方法（`review_record.py sample` の種。却下の行 3 件）、件数、合格・不合格の件数 |
| 問いの回答 | 短い一覧で出た問いの数と、答えた数（Yes／No／該当なしの件数）。答えなかった問いと、その理由（時間・条件に当たらない など）。辿った開いた問いの ID |

## 2. 指摘の一覧

| ID | 場所 | 内容 | 重大度 | 出どころ | 種別 | 取り違えた問い（種別が目的と仕組みの不一致のとき） | 判定 |
| --- | --- | --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |  |  |

- 場所は、設計書の項目 ID（`template:00_core#hop-table`）、台帳の行の ID と列（`C-roles.volatility`）、25 問の番号（`claim_request_roles.md の問 13`）、観点書の問い ID（`q-hop-lifetime`）のうち、当てはまるものを全部書く

## 3. 対応の一覧

| 指摘 ID | 担当 | 期限 | 状態 | 対応の PR・コミット |
| --- | --- | --- | --- | --- |
|  |  |  |  |  |

## 4. 専門家に回した項目

| 基準の ID（escalation.md） | 行・欄 | 回した先 | 期限 | 結論 |
| --- | --- | --- | --- | --- |
|  |  |  |  |  |

当てはまらなかった基準：（基準の ID を並べる）

## 5. カタログ・観点書・対応表に戻す事項

| 戻す先 | 中身 | 指摘 ID | issue・PR |
| --- | --- | --- | --- |
|  |  |  |  |

## 6. 理由の採点（抜き取り）

| 行の ID | 列 | RR1 | RR2 | RR3 | RR4 | RR5 | RR6 | RR7 | 合否 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |  |  |  |  |

## 7. 点検状況

（人による点検の有無。templates/CONTRIBUTING.md の 3. の文）

## 8. 問いごとの回答

Yes＝満たす、No＝満たさない（または見る欄が空で判定できない・自分の言葉で答えを書けない）、該当なし＝理由を書く。観点書の問いは、どれも Yes が「満たす」の向きに書いてあります。
書くのは、答えた問いだけです（短い一覧の問い。区分 A・B・D の問いには答えません）。「理由」には、自分の言葉の答えを 1 行で書きます。

| 段 | 問い ID | 回答 | 理由（1 行） |
| --- | --- | --- | --- |
|  |  |  |  |
```

<a id="after-form"></a>

## 様式の後ろに足す節

8. の後ろには、節を足せます（道具が作るレポートは、9. に行ごとの判定を足します）。開いた問い（short_list.md の 4.）で辿ったことは、次の節を足して書きます。気づきが 0 件のときも、辿った範囲は書きます。

```markdown
## 開いた問いで辿ったこと

| 開いた問い | 辿った範囲（見た欄・考えた場面） | 気づき（指摘 ID。無ければ「なし」） |
| --- | --- | --- |
|  |  |  |
```

道具が作ったレポートに手で節を足すと、`review_record.py report --check`（生成の結果と 1 字ずつ比べる）は通りません。様式の検査（`review_check.py --report`）は通ります。この食い違いは #62 で直します。

根拠：templates/CONTRIBUTING.md の 2.・3.、research/template-design/gate1.md の 5.、筆者の提案：短い一覧に合わせた記入のしかた（追跡 #56）
