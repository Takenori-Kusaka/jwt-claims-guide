# 追加前の 25 問の記入例：`https://claims.example.com/` の `idp`（シナリオ B）

> **記入例です。推奨ではありません。** ケーススタディのシナリオ B＋C の前提での一例です。様式は `templates/claim_request.md`、問いはガイドのスライド 142・143（slide:p11-pre-add-questions-1、slide:p11-pre-add-questions-2）によります。

- 対象：台帳の `C-idp`（`claims.yaml`）。組織の名前空間の共有クレーム（元の IdP の種類）
- 判定（slide:p11-pre-add-questions-1 の「答えられない問いが残るなら共有クレームにしない」）：**25 問すべてに答えた。共有クレームにする**
- 縮小 Lite でもこの 25 問は必須。台帳の列で答えられる 11 問は台帳から写せる（出どころが「台帳」の行）。手で書くのは 14 問

| # | 問い（スライド 142・143） | 回答 | 出どころ |
| --- | --- | --- | --- |
| 1 | 受け手はこのクレームで何を決めるか | 認可には使わない。orders が監査のログに、どの IdP の利用者の操作かを残す | 台帳：`usage`、`rationale` |
| 2 | 寿命中に値が変わっても困らないか | 困らない（ログインの間は変わらない） | 台帳：`volatility`、`on_revoke` |
| 3 | 既存の標準クレームで表せないか | iss は組織のトークンではいつも STS なので、元の IdP を表せない。元の IdP の種類を名前空間に置く | 台帳：`registered_ref` なし、`rationale` |
| 4 | 自組織の名前空間か。予約名と衝突しないか | 名前空間の中。IdP の種類の語彙（keycloak・entra・okta・cognito・auth0）は組織が持つ | 手書き |
| 5 | 「.」「/」入りの名前を全ての受け手のツールで参照できるか | 受け手は orders だけ（監査の表示）。orders の実装で読める | 手書き |

| 9 | 無い・null・false・空配列の意味は | 無ければ監査に unknown と書く（処理は続ける） | 台帳：`on_missing`、`absent_semantics` |
| 10 | 大文字小文字・空白・比較方法は | 小文字の語彙（keycloak・entra・okta・cognito・auth0）と完全一致 | 手書き |
| 11 | 誰が値を書けるか。自己申告と分けたか | Keycloak の Hardcoded claim マッパーと入口の STS（iss から決める） | 台帳：`authoritative_writer`、`provenance` |

| 13 | 上限は。超えたら失敗か、欠落か | 8 バイト。語彙で閉じている | 台帳：`max_bytes`、`overflow_strategy`、`enforced_at` |
| 14 | 全リクエストに載せる価値があるか。宛先ごとに絞れるか | orders 宛ての INT_AT にだけ載せる | 手書き |
| 15 | 付与するのは単一の発行者だけか | Keycloak のレルム corp と入口の STS | 台帳：`authoritative_writer`、`issuers` |
| 16 | 検証を共通ライブラリで提供するか | orders は表示と監査に使うだけで、照合しない。値は入口の STS が iss から決める | 手書き |
| 17 | ヘッダーに移すとき、同名ヘッダーの偽装（大文字小文字・アンダースコアの変種・重複）を除去するか | ヘッダーに移さない | 手書き |
| 18 | 未検証の値を流すモードは無いか | 該当しない（認可に使わない）。ただし、この値で検証を変える（IdP ごとに緩める）作りは禁じる | 手書き |
| 19 | 知らない受け手が無視しても安全か | 安全（監査の記録だけで、無視しても許可は変わらない） | 手書き |
| 20 | ログに残すか。値かハッシュか。個人情報か | 値のまま記録する。個人情報ではない | 台帳：`log_policy`、`pii_category` |
| 21 | 委任なら act・承認 ID との関係は | 委任のトークンには載せない | 手書き |
| 22 | 台帳に登録し、受け手を把握したか | 登録した（`C-idp`）。受け手は orders | 台帳：`consumers` |

| 24 | 改名・廃止の互換期間と並行発行は | 語彙に IdP を足すときは、受け手（orders の記録）を先に直してから入口が出す | 手書き |
| 25 | 発行前の確認手段と、受け手の条件のテストは | Evaluate で KC_AT の値が keycloak であることを、INT_AT は `schemas/INT_AT.issuer.schema.json` の enum で確かめる | 手書き |
