# 追加前の 25 問の記入例：`https://claims.example.com/` の `v`（シナリオ A）

> **記入例です。推奨ではありません。** ケーススタディのシナリオ A の前提での一例です。様式は `templates/claim_request.md`、問いはスライド 142・143（slide:p11-pre-add-questions-1、slide:p11-pre-add-questions-2）によります。

- 対象：台帳の `C-v`（`claims.yaml`）。組織の名前空間のオブジェクトの構造の版
- 判定：**25 問すべてに答えた。共有クレームにする**

| # | 問い（スライド 142・143） | 回答 | 出どころ |
| --- | --- | --- | --- |
| 1 | 受け手はこのクレームで何を決めるか | saas-api が、名前空間のオブジェクトをどの構造で読むかを決める。知らない版なら拒否する | 台帳：`usage: protocol`、`rationale` |
| 2 | 寿命中に値が変わっても困らないか | 困らない。1 枚のトークンの中で版は変わらない | 台帳：`volatility: never` |
| 3 | 既存の標準クレームで表せないか | 名前空間の構造の版を表す登録名は無い（slide:p04-namespace-object-example の `v`） | 台帳：`registered_ref` なし、`rationale` |
| 4 | 自組織の名前空間か。予約名と衝突しないか | 名前空間のオブジェクトの中。最上位の名前ではない | 手書き |
| 5 | 「.」「/」入りの名前を全ての受け手のツールで参照できるか | 受け手は saas-api だけで、`payload["https://claims.example.com/"].v` で読む | 手書き |
| 6 | トップレベルか、組織のオブジェクトの下か | 組織のオブジェクトの下（最上位の `namespaces[].namespace_version` が指す行） | 台帳：`namespace`、`shape: single` |
| 7 | 型は 1 つか。区切り文字列を避けたか | 文字列 1 つ（"1"） | 台帳：`type: string`、`shape: single` |
| 8 | ID・金額は文字列で運ぶか | 版の番号を数値にせず文字列で運ぶ（"1"） | 手書き |
| 9 | 無い・null・false・空配列の意味は | 無い・null は拒否する。版が分からない構造を読まない | 台帳：`on_missing: 拒否` |
| 10 | 大文字小文字・空白・比較方法は | 知っている版の一覧（"1"）と完全一致で比べる。数値として大小を比べない | 手書き |
| 11 | 誰が値を書けるか。自己申告と分けたか | Keycloak の Hardcoded claim マッパー（段階 ②）。テナントの管理者が変えられるが、知らない版は拒否されるので害は拒否だけ | 台帳：`authoritative_writer` |
| 12 | 名前と不変の ID を出し、ID で照合させるか | 識別子ではない（版の値） | 手書き |
| 13 | 上限は。超えたら失敗か、欠落か | 4 バイト。値域は版の番号で固定 | 台帳：`max_bytes: 4`、`overflow_strategy` |
| 14 | 全リクエストに載せる価値があるか。宛先ごとに絞れるか | 名前空間のオブジェクトを載せる AT にだけ載せる（宛先は saas-api） | 手書き |
| 15 | 付与するのは単一の発行者だけか | テナントのレルムだけ | 台帳：`issuers` |
| 16 | 検証を共通ライブラリで提供するか | saas-api の AT の検証の関数の最初で版を確かめ、版ごとの読み方に分ける | 手書き |
| 17 | ヘッダーに移すとき、同名ヘッダーの偽装を除去するか | ヘッダーに移さない | 手書き |
| 18 | 未検証の値を流すモードは無いか | 無い。知らない版を「最新として読む」動きを作らない | 手書き |
| 19 | 知らない受け手が無視しても安全か | 受け手が無視すると、構造の変更に気づかず古い読み方をする。受け手は saas-api に限り、版を必ず確かめる | 手書き |
| 20 | ログに残すか。値かハッシュか。個人情報か | 値のまま記録する。個人情報ではない | 台帳：`log_policy: 記録する`、`pii_category: 該当なし` |
| 21 | 委任なら act・承認 ID との関係は | 関係ない（構造の版） | 手書き |
| 22 | 台帳に登録し、受け手を把握したか | 登録した（`C-v`）。受け手は saas-api | 台帳：`consumers` |
| 23 | 形式を変えるときの移行計画はあるか | これが移行の仕組みそのもの。構造を変えるときは、saas-api を "1" と "2" の両方に対応させてから、マッパーで "2" を出す（slide:p11-change-procedure） | 手書き |
| 24 | 改名・廃止の互換期間と並行発行は | 古い版の読み方は、古い版で出した最後の AT の受け入れの上限（330 秒）が過ぎてから消す | 手書き |
| 25 | 発行前の確認手段と、受け手の条件のテストは | Keycloak の Evaluate で `v` が "1" で出ることを確かめる。受け手の条件は、`v` が無い・知らない版のトークンを拒否するテスト（#8） | 手書き |
