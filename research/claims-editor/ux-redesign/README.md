## 3. 仮のもの・やっていないこと

- 確認事項の中身（どの問いを、どの性質のときに、どの優先で出すか。平易な問いの文）は issue 56 の `templates/review/triage.yaml` で決まった（main からのマージで取り込んだ。それまでの `tools/build_claims_viewer.py` の仮の表は消した）。既定は優先 1 で、シナリオ B では 168 件のうち 18 件と、答えの決まっていない問い 3 件が出る。優先 2 と残りの問いは「時間があれば」で開く（スクリーンショットは、マージの後に全部撮り直した）
- 「設計書から読めないことだけを 3〜5 問で聞く」は、仕組みだけある（条件に問いの文があれば聞き、答えを review.yaml の `traits` に残す）。issue 56 の条件はどれも設計書から読めるので、いま聞く問いは 0 問
- 「レビューを破棄」は無い（「中断」だけ。記録は残る）。コメントの「修正の提案」は記録するだけで、設計書への適用のボタンは無い
- タブに分けたのはクレームの詳細だけ（トークンの種類・経路の詳細は前のまま）。ダッシュボードの作り直しはしていない
