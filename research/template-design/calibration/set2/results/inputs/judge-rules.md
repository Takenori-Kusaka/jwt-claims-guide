# 判定の規則（初回の手順の 7. の判定の節と、2 組目の手順の 7. の改訂 S2・S4・S5・S7）

## 初回の手順の 7.「どの誤りにも一致しない指摘の判定」

| 判定 | 意味 |
| --- | --- |
| 真（基の設計の欠陥） | 双子の両方にある、本当の欠陥。対照では誤検出に数えない。基の設計の欠陥として記録し、再測定の組では直す |
| 真（埋め込みの副作用） | 埋め込みのせいで生じた、正解の一覧に無い矛盾（seeded のみ）。誤検出に数えない |
| 誤検出 | 設計書の記述が正しいのに、誤りとした |
| 判定できない | 仕様・製品の事実が確かめられない。誤検出にも真にも数えず、件数を別に書く |

- **書き手が理由を付けて見送った点への指摘**（測定前の改訂 R4。例：control-b の 3.1 の送信者制約の見送り、Entra での無効化が次の取り直しまで届かないこと）：
  - 指摘が、書かれた理由を確かめるよう求めるもの（「見送りの理由が要求と合うか確かめてほしい」「この遅れを要求が許すか確認」）なら、誤検出に数えない。「確認の依頼」として件数を別に書く
  - 指摘が欠陥だと言い切り（「〜なので誤り」「〜は不可」）、書かれた理由が要求と矛盾しないなら、誤検出
  - 書かれた理由が要求と矛盾するなら、真（基の設計の欠陥）
- 判定は、レビューにも採点にも関わらない別のセッションが行う。渡すものは、その指摘、その設計書、指摘が触れる仕様の節。seeded の指摘の判定では、正解の一覧も渡す（副作用かを決めるため）
- 採点は、互いに独立した 2 つのセッションが全件を行う。食い違った指摘は、3 つ目のセッションが決める。食い違いの割合を書く

## 2 組目の手順の 7.（初回から変えたこと）

- 一致・得点の規則は初回の 7. と同じ（場所 (a)・核 (b)・取り違えた問い。生成の区間の読み替え R3）
- **判定者に渡すもの**（改訂 S2）：その指摘、その設計書（`materialize` した形）、指摘が触れる仕様の節、seeded の指摘では正解の一覧（`seeded_errors.yaml`）。これ以外を渡さない。採点者の出力、ほかの判定者の出力、清掃の記録、初回の結果は渡さない
- **見送りへの指摘**（改訂 S4。初回の R4 の対象をはっきりさせる）：2 組目の対照は、既知の限界をすべて 3.1 の見送りの行（理由と確かめ方つき）に書いた（8.1）。R4 の判定は 3.1 の見送りの行に当てる。3.1 に無く 12. にだけある「確かめていない前提」への指摘は、R4 でなく通常の判定（真・誤検出・判定できない）にする
- **道具・教材への指摘**（改訂 S5）：設計書でなく、`review_triage.py` の性質の読み方（sheet.md の性質の表）・`claim_lint` の出力（ci-result.txt）・教材の文を指す指摘は、誤検出にも真にも数えず、「道具・教材への指摘」として件数を別に書く。例：control-d の性質「操作ごとの承認」が、承認の記録をトークンの外に持つため「当たらない」と読まれること
- **誤検出の数と割合**（改訂 S7）：「control-c を含む値」と「control-d だけの値」を並べて出し、対照ごとに真（基の設計の欠陥）の件数を別の列に書く
- **結果の分け方**：初回の区分（難しさ・経路・種別・原因）に加えて、目立ちやすさ（3.1）・`hint_derived` の有無（3.2）・`form` が `absent` の誤り・A12 の再試験の誤りを、それぞれ別に並べる
