レビューの結果、指摘は **4 件で、すべて Minor** です。Blocker・Major に当たるもの、種別が「目的と仕組みの不一致」のものはありませんでした。CI は error 0・warn 9 で、warn の 9 件にはどれも理由が書いてあり、理由は通ると判断しました。答えの抜き取りの種は 12、抜き取った行は `C-agency-code`・`C-client-id`・`C-act` です。

## 段 1：性質の表の確かめ（12.・2.・6. を読んで）

sheet.md の 12 の性質は、図と要求に照らして**どれも正しい**と判断しました。補足が 2 点あります。

- **「操作ごとの承認」は「当たらない」で妥当です。** 要求 REQ-05 には 100 万円以上の承認があります。ただし承認は payment-svc の記録にあり、トークンには載りません（3.1 で authorization_details を見送り）。この性質の問いのうち `q-approval-from-as` は、「委任がある」の性質から出ているので答えました。
- **「長時間・非同期」は、sheet.md が読んだ欄が弱いです。** 読んだ欄は PH_AT の `long_running` ですが、その値は「使わない」です。この性質に当たる本当の根拠は `PAY_MSG_CTX`、ホップ H20・H21（broker_connection）、U13 の「該当」です。当たるという結論は変わりません。

## 段 2：6. の「要る」問いと判断の木

6. で「要る」とした問いは、どれも判断の木の節と仕組みが合っていました。

| 問い | 判断の木の節 | 設計の仕組み |
| --- | --- | --- |
| q-sub | keep-sub-exchange | 作り直しの後も sub を保つ。payment-batch は自分の ID で、利用者の sub を作らない |
| q-actor（UC3） | keep-sub-exchange | 外側の act だけで、入れ子を作らない |
| q-req-wl・q-txn | txn-tctx | 経路で受けるすべての受け手が tctx を本文と照らす。Txn-Token は専用のヘッダーで運ぶ |
| q-peer | peer-mtls | mTLS。req_wl を直接の相手とみなしていない |
| q-holder（UC2） | — | cnf |
| q-authorized | rar-vs-custom | scope。承認は PDP 側の記録（3.1 で見送りの理由あり） |

UC4 の q-actor を「不要」とした点だけ迷いました。判断の木は、非同期のワーカーを act に入れる形を示しています。設計は、payment-worker は中身を変えられない運び手だとし、運んだワークロードを req_wl と mTLS で別に記録しています。payment.instruct は payment-worker からしか受けないので、監査で人の操作と見分けられます。そのため指摘にはしていません。

## 段 4：開いた問いで辿った範囲と気づき

- **op-proof-holder（鍵の持ち主）：** 鍵を確かめる箇所は、H31（shirogane-as の tls_client_auth で、cnf に証明書の拇印を書く）、H5（front-gw が TLS の拇印と cnf を照らす）、H6（TTS が front-gw の書いたヘッダーと照らす。ヘッダーは front-gw の SPIFFE ID からだけ読み、外から来た同名のヘッダーは捨てる）です。どこでも「トークンを持つ者」と「鍵を持つ者」は代理店のサーバーで一致していました。証明書の更新は同じサブジェクトで出し直し、古い証明書に束縛した AT は最大 300 秒で使えなくなります。ただし CRL を取り直せない間は、失効した証明書も最長 3600 秒受け入れます（3.1 で受け入れた限界）。
- **op-source-change（元データの変化）：** 「査定担当者の退職」を辿りました。人事部の入力と承認で社員の台帳が変わり、TTS の 60 秒のキャッシュの後は発行されず、Txn-Token の 330 秒で、最悪 390 秒で止まります。ブローカーで待っている PAY_MSG_CTX は、作り直しのときに拒まれて滞留のキューに移ります。発効から台帳の更新までの区間は、3.1 で要求の持ち主が受け入れています。気づいた点は、通話の記録の「担当の社員」の出どころが書かれていないことです（指摘 F2）。
- **op-one-time（1 回だけ使える値）：** 認可コード、登録の番号、支払いの指示の一意の制約、実行、保留の印は、並行の 2 件・再送・記録先の障害のどれでも 2 回通らず、正しい 1 回も落ちません。代理店の assertion の jti だけ、覚える期間と受け入れる期間がずれます（指摘 F4）。
