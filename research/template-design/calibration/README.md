# 誤りを埋め込んだ設計書と対照（#12 の測定の教材）

> **意図的に誤りを含む教材。設計に使わない**
>
> `seeded-a/`・`seeded-b/` の設計書には、問いの取り違えを意図的に埋め込んでいます。`control-a/`・`control-b/` は、測定の対照に使う架空のシステムの設計書で、実在のシステムの設計ではありません。どれも、写して設計に使わないでください。

> **LLM による測定。人による検証ではない。**
> 教材の作成・正解の一覧・これから行う測定は、どれも LLM（Claude）のセッションが行います。人による測定は #20 で行います。

#12 の目的は、テンプレート・観点書・判断の木・対比表だけを渡されたレビュアーが、問いの取り違えを見つけられるかを測ることです。この PR は、**測定の前に**教材と正解と目標を固定するところまでです。測定はまだ行っていません。

## 中身

| パス | 中身 |
| --- | --- |
| [`protocol.md`](protocol.md) | 測定の手順・難しさの区分・目標の値・採点の規則・ブラインドの決まり・再測定の計画 |
| [`seeded_errors.yaml`](seeded_errors.yaml) | 埋め込んだ誤りの一覧（正解）。場所・何が誤りか・種別・取り違えた問い・根拠（版付き）・難しさ・見つけるはずの経路。**レビュアーに渡さない** |
| [`expected_lint.yaml`](expected_lint.yaml) | 4 つの設計書の claim_lint の結果（error・warn・info の件数と warn の行）。CI が実際の結果と比べる |
| [`commitments.sha256`](commitments.sha256) | 目標と正解と設計書の sha256。測定の前に固定したことを、コミットの時刻と合わせて示す |
| `seeded-a/` | 誤りを埋め込んだ設計書 A（P4：AI エージェントの委任が中心）。ファイル名に `.broken` |
| `control-a/` | A の対照。A と同じ設計で、誤りを埋め込む前のもの |
| `seeded-b/` | 誤りを埋め込んだ設計書 B（P5：内部の伝搬・ワークロード・トークンの交換が中心）。ファイル名に `.broken` |
| `control-b/` | B の対照。B と同じ設計で、誤りを埋め込む前のもの |

- 対照は、埋め込む前の設計書そのもの（双子）です。誤検出を、同じ大きさ・同じ複雑さの設計書で測るためです。レビュアーは 1 つのセッションで 1 つの設計書しか読まないので、双子を見比べることはできません（`protocol.md` の 6.）
- 題材は架空の 2 つのシステムで、記入例（`templates/examples/`）とパイロット（`research/pilot/`）とは別の領域・別の名前で新しく書きました。どちらかを読んだレビュアーが、答えを覚えていて見つける、ということを避けるためです
- 各ファイルの中の印は、`templates/CONTRIBUTING.md` の 4.（意図的に誤りを含む教材）の形です。`tools/calibration_check.py materialize` が印を 1 字ずつ外し、`.broken` を名前から外して、レビュアーに渡す形（と claim_lint・render が読む形）を作ります

## 検査

```
python tools/calibration_check.py check                     # C1〜C6（CI の trace のワークフロー）
python tools/calibration_check.py materialize seeded-a OUT  # レビュアーが受け取る形
python tools/calibration_check.py packet seeded-a OUT        # 1 回のレビューの資料一式（protocol.md の 6.）。設計書は OUT/designs/target に入る
```

## 作成方法と点検状況

- 作成方法：本資料は生成AI（Claude）を使って作成し、筆者が確認して公開しています
- 点検状況：人による点検は未実施。正解の一覧と設計書の対応は、`calibration_check.py` の C4（場所が実在する）と、対照との差分（埋め込んだ誤りだけが差分になる）で機械的に確かめた。誤りの中身と、対照に誤りが無いことは、別の LLM のセッションでも人でも点検していない（測定の採点で、対照の指摘を 1 件ずつ判定する。`protocol.md` の 7.）
