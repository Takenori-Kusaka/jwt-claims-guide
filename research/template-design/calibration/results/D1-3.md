# JWT クレーム設計書 designs/target レビュー結果（種 12）

読んだ範囲は、設計書の全節（1.〜13.、付録 A〜D）と、claims.yaml・hops.yaml・token_types.yaml・catalog_answers.yaml です。ci-result.txt は error 0 で OK でした。ただし、機械の検査は宣言どうしの整合しか見ません。下の指摘の多くは、整合したまま中身が誤っているものです。

## 手順 1：性質の表の確認

- 当たる／当たらないの判定は、台帳と図に照らしてほぼ正しいです。確かめたのは次の項目です。
  - 当たる：複数 IdP、交換・再発行（H6〜H9）、委任（C-act）、マルチテナント、DB（H14〜H17）、auth_time、送信者制約の見送り、非同期（H11 の broker_connection）。
  - 当たらない：送信者制約を選んだ。
- 「操作ごとの承認がある」を「当たらない」としたのは不十分です。authorization_details は無いものの、break-glass の approval_id と tctx（operation・declared_value などの object 型）が、操作単位の承認として働いています。dc-05（object の内側の型と比べ方）も答える対象です。指摘 F22 を参照してください。
- 長時間・非同期の根拠の欄は AUTH0_AT の long_running になっています。この行は「使わない」なので根拠として弱いです。実際に当たる根拠は、TXN_TOKEN の long_running と H11 です。結論は変わりません。
- 検査を通すために宣言側を曲げた跡が複数あります。F12・F13 を参照してください。
  - PARTNER_AT の hop の max_lifetime が、token の 86400 でなく 600 になっています。
  - C-entra の volatility に、許容として 28800 を書いています。
  - 9.2 の鮮度の表に「超える行が無い」と書いています。

## 手順 4：開いた問い 3 つ

**op-source-change**
- 出来事は「荷主の社員の退職（Entra のみのユーザー）」と「ロール剥奪」を選び、IdP の手前から辿りました。
- 退職の経路：
  1. 荷主の Entra 管理者がユーザーを無効化します。
  2. Auth0 には通知されません（SSF/CAEP と Back-Channel Logout を見送り済み）。
  3. 荷主の管理者が、はこぶねの画面でメンバーを手で止めます。ここは誰も時間を約束していません。
  4. 止めなければ、Entra のグループやメールの値が Auth0 のセッションと RT の最大 28800 秒のあいだ残ります。
  5. 止めても、edge-gw の 24 時間キャッシュ（U21）が残ります。
- ロール剥奪の経路：
  1. 荷主の管理者が、はこぶねの画面で割り当てます。
  2. はこぶねが Auth0 の管理 API で書きます。
  3. 次の取り直しで AT に反映されます（最大 630 秒）。
  4. 手前の edge-gw のキャッシュが効いていると、反映されません。
- 気づいたこと：
  - 「画面 → Auth0 管理 API」の書き込みを行う部品と、メンバーの表を書く部品が、2. の図に出ていません。
  - メンバーの表の書き手の記述も食い違っています。C-sub は「TTS だけが書く」、C-tenant-id は「申し込みの処理だけが書く」と書いています。
  - これらは F19 にしました。

**op-one-time**
- 辿ったのは認可コード・CLIENT_ASSERTION の jti・label-svc の再配送・break-glass の approval_id です。
- 認可コード：1 回だけ使え、60 秒です。
- CLIENT_ASSERTION：Auth0 が jti の再送を拒む前提ですが、確かめていません（12.）。
- label-svc の再配送：「同じ txn と荷物の ID を 2 回作らない」とだけあります。並行 2 件のときの一意制約や、確かめてから使用済みにするまでの順序がありません。
- approval_id：60 分の間は何度でも使えます。1 回限りかどうかが決めてありません。
- 指摘は F25（Minor）にしました。

**op-clock**
- 比べる 2 つの時刻が別の時計になる箇所は次のとおりです。
  - auth_time（Auth0 の時計）と web-bff の時計の比較（300 秒）。ずれの許容も、未来の値の拒否もありません。
  - break-glass の期限を、TTS と billing-svc がそれぞれ自分の時計で見ます。
  - label-svc は exp を見ません。
- 指摘は F24（Minor）にしました。
