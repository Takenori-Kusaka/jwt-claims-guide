## 結論

designs/target の設計書を、sheet.md の問いの順にレビューしました。指摘は 29 件で、内訳は Blocker 4、Major 17、Minor 8 です。優先 1 の 18 問のうち、Yes は q-agent-short-lived-no-rt の 1 問だけでした。

マージの前に直す必要があるのは次の 4 件の Blocker です。
- **縮退の運転（F01）**：TTS が止まると、各サービスが X-Tenant-Id・X-User-Id のヘッダーをそのまま信じます。テナントも利用者も偽れます。
- **report-svc の任意の SQL（F02）**：BYPASSRLS を持つ接続に、利用者が書いた SQL を流します。ほかのテナントの行に届きます。
- **Entra の利用者を mail で決める（F03）**：利用者もテナントも、Entra の管理者が書き換えられる mail とそのドメインで決めています。
- **メールでの名寄せ（F04）**：同じメールの人を 1 人にまとめており、要求の 6 節（別の荷主なら別の利用者）に反します。F03 と重なると、別の荷主の口座を乗っ取れます。

CI は error 0・warn 5 で、warn にはすべて理由が書いてありました。

## 3. 開いた問い（sheet.md の 5.）

**op-source-change**
- 辿った範囲：
  - 出来事 (a)「荷主の社員が異動で Entra の admin のグループから外れる」・「退職で Entra のアカウントを止める」
  - 出来事 (b)「Auth0 のデータベースの接続の利用者のロールを外す」
- 経路 (a)：荷主の人事 → 荷主の Entra の管理者 → Entra → Auth0 → post-login の Action → AUTH0_AT → TTS。
  - Auth0 が Entra の値を取り込むのは、Entra を通るログインのときだけ。web-bff が RT で取り直しても Entra には問い合わせないので、最大 28800 秒は古い groups の admin が TTS に届く。
  - Entra でアカウントを止めた後も、RT と Auth0 のセッションが残る（SSF・CAEP は見送り）。
  - はこぶねのメンバーの表は、荷主の管理者が別に手で止めない限り変わらない。
  - さらに edge-gw が「利用者を通してよいか」を 24 時間キャッシュする（U21）。
- 経路 (b)：はこぶねの画面 → Auth0 の管理の API への書き込み → 次の取り直し（最大 630 秒）→ TTS。管理の API への書き込みが失敗したときの再試行と、その時間の約束が無い。
- 誰も時間を約束していない区間：Entra → Auth0、管理の API への書き込み、edge-gw のキャッシュ。要求に役割の変更の遅れの数値が無い（F05・F17）。

**op-one-time**
- 辿った値：AUTH_CODE（Auth0 が持つ）、CLIENT_ASSERTION の jti（Auth0 が再送を拒む前提だが、未確認。12.）、RT の再利用の検知（unverified）、break-glass の approval_id、ラベル作成の重複防止（txn と荷物の ID）、請求の書き込み（H10）。
- 気づき：
  - approval_id は 1 回ではなく、60 分の間なら何度でも使える。承認が個々の操作に結びついていない（F22）。
  - ラベルの重複防止は「確かめる」と「使用済みにする」が分かれているかが書いていない。記録先が止まったときの挙動も無い。キューの再配送を 2 つのインスタンスが同時に受けると、2 回通る余地がある。
  - H10 の請求の書き込みには、再送に備えた冪等のキーが無い。請求が重なりうる（F26）。

**op-clock**
- 辿った箇所：exp・iat（発行者の時計と受け手の時計。ずれ 30 秒）、auth_time（Auth0 の時計）と web-bff の「300 秒以内」、break-glass の期限（申請の記録の時計）と TTS・billing-svc、Webhook の created（はこぶねの時計）と運送会社の 300 秒。
- 気づき：
  - `C-exp` の前提は「1 秒以内にそろう」、見直しの条件は「30 秒を超えたとき」で、言っていることが合わない。
  - 申請の期限と auth_time は、どの時計で比べ、ずれたら通すのか止めるのかが書いていない。
  - 矢印の表は、Auth0 が出す PARTNER_AT（86400 秒）と SVC_AT（600 秒）にも「exp − iat ≤ 300」を当てている。書いたとおりに作れば、正しいトークンをすべて拒む（F14）。
  - label-svc は期限そのものを見ない（F08）。
