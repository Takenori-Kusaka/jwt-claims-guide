# 追加前の 25 問：`https://minato-denki.example/claims/` の `customer_contact`

> **意図的に誤りを含む教材。設計に使わない**

- 対象：台帳の `C-customer-contact`（claims.yaml）
- 判定：共有クレームにする（25 問すべてに答えた）

| # | 問い（スライド 142・143） | 回答 | 出どころ |
| --- | --- | --- | --- |
| 1 | 受け手はこのクレームで何を決めるか | 決めない（usage は display）。3 つのツールが、操作の結果を顧客に知らせる宛先に使う | 台帳：`usage`・`answers`・`rationale` |
| 2 | 寿命中に値が変わっても困らないか | 困らない（volatility は 86400）。連絡先は滅多に変わらず、次の交換で新しい値になる | 台帳：`volatility`・`on_revoke` |
| 3 | 既存の標準クレームで表せないか | 登録名の email・phone_number はトークンの主体（担当者）の連絡先なので、顧客の連絡先に使うと取り違える（prior_art_search） | 台帳：`registered_ref`・`prior_art_search` |
| 4 | 自組織の名前空間か。予約名と衝突しないか | 自組織の名前空間 https://minato-denki.example/claims/ の下 | 手書き |
| 5 | 「.」「/」入りの名前を全ての受け手のツールで参照できるか | 受け手はどれも組織の共通の検証部品で、完全一致のキーとして読む | 手書き |
| 6 | トップレベルか、組織のオブジェクトの下か | トップレベルに、名前空間の接頭辞つきの名前で置く（flat_prefix）。値は email と phone の 2 つのメンバーのオブジェクト | 台帳：`namespace`・`shape` |
| 7 | 型は 1 つか。区切り文字列を避けたか | オブジェクト 1 つ（shape は single）。メンバーはどちらも文字列 | 台帳：`type`・`shape` |
| 8 | ID・金額は文字列で運ぶか | 電話番号は E.164 の文字列で運ぶ | 手書き |
| 9 | 無い・null・false・空配列の意味は | 無ければ顧客に知らせない（担当者が電話で知らせる） | 台帳：`absent_semantics`・`on_missing` |
| 10 | 大文字小文字・空白・比較方法は | 比べない（送り先に使うだけ）。メールは顧客の DB の値のまま | 手書き |
| 11 | 誰が値を書けるか。自己申告と分けたか | agent-sts だけが、案件の管理から引いた顧客の DB の値を書く | 台帳：`authoritative_writer`・`provenance` |
| 12 | 名前と不変の ID を出し、ID で照合させるか | 照合には customer_ref を使い、連絡先では照合しない | 手書き |
| 13 | 上限は。超えたら失敗か、欠落か | 300 バイト。超えたら発行を失敗させる | 台帳：`max_bytes`・`max_items`・`overflow_strategy` |
| 14 | 全リクエストに載せる価値があるか。宛先ごとに絞れるか | 3 つのツールがどれも顧客に知らせるので、エージェントの経路の TOOL_AT に載せる | 手書き |
| 15 | 付与するのは単一の発行者だけか | agent-sts だけ（issuers） | 台帳：`issuers`・`enforced_at` |
| 16 | 検証を共通ライブラリで提供するか | 形式の検査は共通の検証部品が行う | 手書き |
| 17 | ヘッダーに移すとき、同名ヘッダーの偽装（大文字小文字・アンダースコアの変種・重複）を除去するか | ヘッダーに移さない | 手書き |
| 18 | 未検証の値を流すモードは無いか | 無い | 手書き |
| 19 | 知らない受け手が無視しても安全か | 安全。知らせの宛先に使うだけで、権限は広がらない | 手書き |
| 20 | ログに残すか。値かハッシュか。個人情報か | 個人情報。ログには記録しない | 台帳：`log_policy`・`pii_category` |
| 21 | 委任なら act・承認 ID との関係は | 関係しない（操作の対象の顧客の連絡先） | 手書き |
| 22 | 台帳に登録し、受け手を把握したか | 登録した。受け手は order-tool・refund-tool・customer-tool | 台帳：`consumers` |
| 23 | 形式を変えるときの移行計画はあるか | メンバーを足すときは、受け手が知らないメンバーを無視することを確かめてから足す | 手書き |
| 24 | 改名・廃止の互換期間と並行発行は | TOOL_AT の受け入れの上限（1830 秒）より長く、少なくとも 2 週間は並行して出す | 手書き |
| 25 | 発行前の確認手段と、受け手の条件のテストは | agent-sts の結合試験で、案件の顧客の連絡先が載り、ほかの顧客の連絡先が載らないことを確かめる | 手書き |
