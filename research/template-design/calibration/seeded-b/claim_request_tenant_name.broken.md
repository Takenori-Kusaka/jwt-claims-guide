# 追加前の 25 問：`https://hakobune.example/claims/` の `tenant_name`

> **意図的に誤りを含む教材。設計に使わない**
- 対象：台帳の `C-tenant-name`（claims.yaml）
- 判定：共有クレームにする

| # | 問い（スライド 142・143） | 回答 | 出どころ |
| --- | --- | --- | --- |
| 1 | 受け手はこのクレームで何を決めるか | billing-svc が、請求書の宛名と、どの料金の表を使うかを決める（usage: display） | 台帳：`usage`・`answers`・`rationale` |
| 2 | 寿命中に値が変わっても困らないか | 表示名を変えても、TXN_TOKEN の寿命（最大 330 秒）の間は前の名前が残る。請求の締めは夜間なので困らない | 台帳：`volatility`・`on_revoke` |
| 3 | 既存の標準クレームで表せないか | IANA の JWT Claims に組織の表示名の登録名は無い。Auth0 の org_name は Auth0 の組織の名前で、内側のトークンには載らない | 台帳：`registered_ref`・`prior_art_search` |
| 4 | 自組織の名前空間か。予約名と衝突しないか | はこぶねの https://hakobune.example/claims/ の下 | 手書き |
| 5 | 「.」「/」入りの名前を全ての受け手のツールで参照できるか | 受け手は billing-svc だけで、共通の検証部品の関数で読む | 手書き |
| 6 | トップレベルか、組織のオブジェクトの下か | トップレベルの、名前空間を前に付けた名前（flat_prefix） | 台帳：`namespace`・`shape` |
| 7 | 型は 1 つか。区切り文字列を避けたか | 文字列 1 つ | 台帳：`type`・`shape` |

| 9 | 無い・null・false・空配列の意味は | 無ければ拒否する（料金の表を選べない） | 台帳：`absent_semantics`・`on_missing` |
| 10 | 大文字小文字・空白・比較方法は | テナントの台帳の表示名をそのまま写し、料金の表の名前と完全一致で比べる | 手書き |
| 11 | 誰が値を書けるか。自己申告と分けたか | TTS がテナントの台帳から書く。台帳の表示名は荷主の管理者がはこぶねの画面で変えられる（provenance: 管理者が設定した値） | 台帳：`authoritative_writer`・`provenance` |
| 12 | 名前と不変の ID を出し、ID で照合させるか | 不変の ID は tenant_id で別に出す。tenant_name は表示と料金の表の選択に使う | 手書き |
| 13 | 上限は。超えたら失敗か、欠落か | 120 バイト。超えたら発行を失敗させる | 台帳：`max_bytes`・`max_items`・`overflow_strategy` |
| 14 | 全リクエストに載せる価値があるか。宛先ごとに絞れるか | billing-svc に届くホップ（運用者の代理・夜間の締め）にだけ載せる | 手書き |
| 15 | 付与するのは単一の発行者だけか | TTS だけ | 台帳：`issuers`・`enforced_at` |
| 16 | 検証を共通ライブラリで提供するか | 共通の検証部品が読み、billing-svc に渡す | 手書き |
| 17 | ヘッダーに移すとき、同名ヘッダーの偽装（大文字小文字・アンダースコアの変種・重複）を除去するか | ヘッダーに移さない | 手書き |
| 18 | 未検証の値を流すモードは無いか | 無い。署名を検証した Txn-Token からだけ読む | 手書き |

| 20 | ログに残すか。値かハッシュか。個人情報か | 値のまま残す。法人の名前で、個人情報ではない | 台帳：`log_policy`・`pii_category` |
